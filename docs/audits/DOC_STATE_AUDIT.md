# DOC-STATE-AUDIT-01 — состояние документации NetMap

## 1. Executive summary

На проверенной базе доступны обычная коммутация 1:1, пассивная парная continuity, шаблоны и установки модулей, карта с автоматической маршрутизацией и L1 trace с каноническим evidence. Четыре недавних кабельных workflow имеют задокументированную ручную приёмку в конкретных сценариях. Ни L1 CONNECTIVITY COMPLETE, ни L1 PRODUCT COMPLETE пока не достигнуты.

Главный инженерный разрыв проходит между выразимостью core и рабочим циклом. BaseTemplate уже материализует точно заданную многоканальную разводку. Внешняя запись, занятость с учётом роли и канала, редактирование mappings, техническая совместимость и пользовательская приёмка точного trace для trunk остаются открыты. Для модулей отдельно нужны пассивная continuity, рекурсивная установка и ограниченный lifecycle трансивера с сохранением интерфейса. Граница duplex и смены аппаратного режима требует решения.

Для продукта обязательны IA-01–IA-06, рабочая изоляция и доступ, PERF-002–005 и итоговая приёмка. Независимые сети карт и переносимые определения уже приняты как target reference network. Их место в очереди зависит от границ владения и формата определений. Запуск demo при инициализации предлагается отдельно вынести на решение об обязательности.

Предложение для внешнего review — вывести закрытые A/B из будущей очереди, перенести инженерную часть D перед сквозной C, объединить работу E/G по пользовательским сценариям, определить владение до массовых новых writes, измерять H по ходу реализации и провести один итоговый сквозной reference run в I. Подтверждено **5 противоречий** (§13.A), адресно разобрано **20 спорных групп статусов** (§4), проверено **10 рабочих документов** (§3).

- Принятые требования берутся из текущих контрактов. Состояние определяется по адресным моделям, API, write paths, resolver и экранным entry points. Существующие тесты и артефакты аудитов используются как evidence и история решений. Ручная приёмка учитывается в границах записанного сценария.
- IMPLEMENTED — путь присутствует. ACCEPTED / VERIFIED — есть явное evidence приёмки указанного сценария. PARTIAL — отдельные части существуют. OPEN — определённая работа остаётся. RECHECK REQUIRED — доступный путь требует перепроверки. DECIDED TARGET — принято требование. OBSOLETE / NOT REQUIRED — заменённая или исключённая работа. BLOCKED — конкретная незакрытая зависимость. MERGED — факт git history.

## 7. L1 connectivity vs product completeness

**CONNECTIVITY COMPLETE** означает завершённые A-пути и доказанный цикл на узких representative fixtures. Создать реальные окончания и типы, материализовать passive chain, провести copper 1:1 и один optical multichannel trunk с permutation/subset, проверить конфликт, переподключение, удаление, reload и exact evidence. Проверить отдельно поддерживаемую модульную конструкцию и сохранение interface identity. Для duplex и рекурсивных модулей требуется явно зафиксировать минимальный scope и сценарии, которых нет в reference fixture. Предложение по уточнению gate: duplex verdict нужен, чтобы заявления о полноте оптики имели конкретную область. Решение может потребовать небольшой дополнительный case.

**PRODUCT COMPLETE** включает CONNECTIVITY, IA-01–06, usability/scale, persisted workspace/auth/access/sharing/accountability и финальное operational evidence. Независимость карт и переносимость предлагается явно связать с I как условия принятого reference roundtrip. Полную независимость прав можно вводить после инженерных проверок, но canonical ownership влияет на writes/evidence и требует раннего design и тестируемой границы. Отсрочить её до конца G означало бы переделывать scope reads, constraints и data transition сразу в нескольких путях.

## 13. Conflicts and open product decisions

### A. Подтверждённые противоречия

1. **O5 и обязательность многоконцевой сборки.** ARCHITECTURE и «пересмотр» в очереди сохраняют старую активную формулировку одной identity для сборки с несколькими ends. L1-CONTRACT-03 прямо относит её к истории и оставляет семантику/обязательность OPEN. Двухточечный trunk остаётся обязательным. [Старая норма](../ARCHITECTURE.md#принятые-l1-инварианты--l1-contract-02) · [Действующее уточнение](../L1_CONNECTIVITY.md#принятые-решения-l1-o1l1-o10--decided).
2. **Полный collapse в uniform-grid.** Обобщённый CURRENT обещает скрыть всех потомков даже при пустом наборе видимых. Проверенный browser case оставляет устройства. Между проверенным кодом и baseline новых runtime правок нет. Область расхождения подтверждена, причина и corrective verification открыты. [CURRENT](../ARCHITECTURE.md#savedmap-варианты-и-spatial-isolation) · [Evidence](L1_READINESS_AUDIT.md#l1a-01--полный-collapse-в-uniform-grid-оставляет-дочернее-оборудование).
3. **Размер объекта и прежний top nameplate.** Описание фактически отрисованного top footprint в ранних CURRENT blocks расходится с трёхзонной рамкой и текущим backend расчётом. Живая политика сохраняет composition width и side zones. [ARCHITECTURE](../ARCHITECTURE.md#savedmap-варианты-и-spatial-isolation) · [OBJECT-UX](https://github.com/scvarr/netmap/blob/c4297f08cec11d18a71ca0c23cdd7176a1218fbf/docs/OBJECT-UX-01.md) · [Geometry](../../app/object_frame_geometry.py).
4. **Выполнимость gates C/D.** Phase C до D требует «обязательные fixes» и clean representative UI. Её же обязательный finding — C-CAP-01, перенесённый в D. Полный reference сценарий явно требует trunk write, typed Cable и isolation, которых к C по порядку ещё нет. Ранний discovery C возможен, термин «acceptance» здесь задаёт несовместимую зависимость. [Очередь](https://github.com/scvarr/netmap/blob/c4297f08cec11d18a71ca0c23cdd7176a1218fbf/docs/BACKLOG.md#последовательность-phase-ai) · [Reference evidence](../L1_REFERENCE_NETWORK.md#приёмка-и-evidence--будущий-запуск).
5. **Отображение немаркированного Cable.** Принятый target задаёт RU fallback «Без маркировки · <короткий ID>». Текущий resolver возвращает `Cable <короткий ID>`. Это конкретное расхождение текста target и runtime, сохранение UUID и display-only semantics уже соблюдены. [UX/IA](../UX_IA_CONTRACT.md#маркировка-cable) · [Code](../../app/cable_labels.py).

### B. Устаревшие требования и поручения

- «Следующий L1 readiness audit» выполнен. Результаты оставляют defects/rechecks, а не повтор поручения.
- Отдельная физическая FRONT/REAR taxonomy C-UX-03 исключена. Variant views сохраняются как presentation.
- Old Blueprint API, MapComposite/MapRegion, индивидуальные persisted Cable routes и прежний PortBlock catalog исключены. Не вводить совместимость для старого authoring. Исторические canonical data, identities и retained immutable snapshots защищены текущим контрактом.

### C. Неполные implementation contracts

- C-CAP-01 требует decisions о stable addressing/provenance, integer members и роли connections, validation/concurrency, write DTO и атомарных edit/reconnect/disconnect, reconcile, UI и ожиданиях для group trace. 01 остаётся реализованным, 02–04 сохраняют acceptance criteria до явного пересмотра.
- Typed definitions требуют защиты активных и historical references, policies для архивирования и перехода существующих Cable. Процесс обновления схемы — forward-only.
- Nested installations и passive module continuity требуют consistent lifecycle, bindings и запрета циклов. Текущая проверка удаления не определяет полноценную замену.
- Независимые карты требуют согласованных FK/transaction/read scopes, перехода общих текущих placements и API, переноса reference libraries и negative cross-map tests. Scope пакетов и sharing зависит от владения.
- IA требует явного URL/history state и семантики недоступной ссылки. PERF требует выборки page/total и измеримых бюджетов. Отсутствие измерений не доказывает ни достаточную производительность, ни необходимость заранее внедрить LOD.

### E. Рекомендации по обязательности

- Обязательность C-CAP-01, CAT-D minimum, IA-01–06, F и PERF-002–005 сохраняется. Предлагается явно связать independent maps и portable definitions с итоговым reference gate, поскольку контракт требует cross-map negative case и roundtrip.
- Предлагается считать подтверждённый uniform-grid collapse [#2](https://github.com/scvarr/netmap/issues/2) blocker финальной продуктовой приёмки. Принятый workflow оставляет скрытые объекты видимыми и даёт ложное представление путей. Отдельный targeted browser recheck нужен после corrective. Перегрузка меню [#1](https://github.com/scvarr/netmap/issues/1) остаётся UX debt, кроме конкретных нарушений принятых IA criteria.
- Для инженерного gate предлагается явно согласовать минимум passive module и duplex workflow. Основание — принятая рекурсивная модульная семантика и требование полноты базовой оптической инфраструктуры. Scope тестов и fate подключённого Cable сначала согласовать. Demo auto-init, специализированная оптика, расширенные taxonomy, guides, telemetry и compression остаются отдельными решениями.
- Статус «нет реализации» применять к конкретному пути. Отсутствие запуска в этом аудите, отсутствие regression test, отсутствие ручной приёмки и открытое продуктовое решение фиксируются отдельно.
