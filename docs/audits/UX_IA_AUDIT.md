# UX-IA-AUDIT-01 · NetMap

## 1. Executive summary

Оборудование можно создать из BaseTemplate, привязать к стойке и открыть
физические порты. При обратной задаче, когда известна стойка, каталог не
позволяет найти её оборудование по Location. В кабельном каталоге текстовый
поиск пригоден для известной маркировки, а отбор по сочетанию устройства и
окончания и сортировка по концам отсутствуют. При переходах между каталогом,
карточками и редакторами теряется рабочий контекст.

В диалоге «Добавить дочернее» родитель выбран правильно и кнопка сохранения
доступна на обоих размерах. Проблема в том, что форма показывает все ветви и
позволяет сменить родителя одним щелчком. В форме серии выявлено более
серьёзное препятствие: после прокрутки за высоким деревом кнопка отмены
перекрывается сайдбаром.

Рекомендуемый порядок обсуждения — восстановить управление диалогами,
согласовать навигацию и возврат, затем улучшить инвентаризацию по Location и
окончаниям. Приоритеты отражают стоимость ошибки и повторяемость задач.
Предложения требуют внешнего review и отдельного согласования.

## 2. Scope, environment, methodology, limitations

20.11.2026, ветка `audit/ux-ia-audit-01`, база
`03f2f70191b9736aa5b2ba98a9ca07684277cb8a`. Chromium через Playwright
(Microsoft Edge), RU, 1440×1000 и 1024×768. Изолированный Docker Compose
проект `netmap-ux-ia-audit-01` на порту 5174, миграции выполнены при
старте, отдельная БД в томе экземпляра Postgres. Синтетические данные
`AUD-*` созданы в интерфейсе. Пользовательский стенд на 5173 оставался
отдельным. Экспертный обход, наблюдение DOM, доступных имён, URL, состояний
и геометрии. Числа действий приведены только для записанных проходов,
без учёта подготовки данных и программных ожиданий. Нагрузочный замер,
участники, screen reader, мобильный UX и полный WCAG-аудит вне охвата.

Сверены [AGENTS](../../AGENTS.md), [архитектура](../ARCHITECTURE.md),
[состояние](../PROJECT_STATE.md), [backlog](../BACKLOG.md),

## 4. Navigation and naming inconsistencies

«Объекты» в сайдбаре скрывает наличие кабелей, а «Каталог» в H1 меняет
термин в момент перехода. «Объекты» в крошках шаблонов имён создаёт ложное
вложение. Библиотека называется «Шаблоны объектов» даже при наличии вкладки
«Модули». У создания BaseTemplate подряд две «Библиотеки», из которых
только одна является переходом. На Locations и PortType рубрика и текущий
экран повторяются между крошками, eyebrow и H1. Данные NetMap показывают
крошку из одного текущего элемента. [Шаблоны имён](ux-ia-audit-evidence/labels-1024.png) · [PageChrome](../../frontend/src/components/PageChrome.tsx).

Холодный URL показывает базовое состояние каталога/библиотеки. Смена
вкладки каталога URL не меняет. На ModuleTemplate sidebar теряет выделение
из-за отдельного префикса маршрута. Для вкладок библиотеки ArrowRight
переключает панель, в каталоге оставляет фокус на исходном элементе и
выбранное «Оборудование». Карточка использует обычные ссылки, что позволяет
открыть конкретный раздел напрямую. На обоих размерах Tab прошёл от бренда через
семь ссылок и язык к первой команде Locations. Исторический аудит
отдельно измерял фокус после перехода. [Порядок Tab](ux-ia-audit-evidence/dialogs.json) · [Клавиатура и холодные URL](ux-ia-audit-evidence/navigation.json) · [Исторический обход](l1-readiness-evidence/ux-review/ux-browser-results.json).

## 8. Cable naming and fallback semantics

`resolved_cable_label` возвращает сохранённую маркировку, а при её
отсутствии формирует `Cable <первые 8 символов UUID>` с маркером
`TECHNICAL_FALLBACK` для каталога. Это отображаемое имя, идентификатор
записи — отдельный UUID. Фолбэк нужен, чтобы различать безымянные строки и
операции. Он попадает в каталог, физические attachments карточки,
bulk-delete/reconnect summaries и L1 projection/trace. Каталог ищет
и сортирует по отображаемой строке, поэтому фолбэки участвуют в общей
natural сортировке по тексту, без отдельного порядка записей «без
маркировки». В rename техническая строка отделена от пользовательского
значения. В браузере поле имени было пустым при технической подсказке.
Ввод AUD-Manual-48 дал одну строку по точному поиску. Генерация по
AUD-Label с паттерном AUD-C-## вывела AUD-C-00, который виден и в обоих
физических окончаниях. [Журнал](ux-ia-audit-evidence/cables.json) · [Смешанные подписи](ux-ia-audit-evidence/cables-mixed-1024.png). [Формирование](../../app/cable_labels.py#L15) · [каталог](../../app/catalog_inventory_resolver.py#L117) · [физика](../../app/physical_object_details_resolver.py#L97) · [операции](../../app/physical_connections.py#L380) · [trace](../../app/topology_projection_resolver.py#L547) · [rename](../../frontend/src/pages/InfrastructureObjectsPage.tsx#L821).

Ручная маркировка и генерация по шаблону создают настоящее сохранённое
значение. Генерация явно запрашивается, например в preview bulk, а
«Без имён» оставляет записи без маркировки. Генератор учитывает
последовательность и историю. Правило уникальности отдельно настраивается,
поэтому сортировка и поиск должны допускать одинаковые пользовательские
имена. В списке кабелей «Без маркировки · a1b2c3d4» делает отсутствие
полевой маркировки явным и сохраняет подсказку для поиска. Предлагается
отдельная группа таких строк в конце сортировки по маркировке, стабильный
UUID tie-break, поиск по короткому ID и полному ID при вставке. Проверить,
как оператор отличает одинаковые короткие префиксы, например по концам и
доступному полному ID. Пользовательская маркировка выводится дословно.
Canonical identity, присвоенные метки, история и immutable revisions
сохраняют свои контракты. [Генерация и сохранение](../../app/cable_labels.py#L103) · [Preview](../../frontend/src/components/BulkCableCreateDialog.tsx#L329).

## 11. Target UX/IA contracts

в sidebar, H1 и ссылках. Рубрика нужна в меню для ориентирования; на

### TABLE UX CONTRACT

1. Сортировка по применимым предметным колонкам, видимые ASC/DESC.
   Кнопка заголовка доступна с клавиатуры, текущее направление объявлено.
2. Natural comparator для чисел в именах (`SW-2 < SW-10`), locale
   определён. Стабильный tie-break по canonical ID при равных значениях.
   Согласовать положение отсутствующих значений, одинаковое на страницах.
3. Для Cable минимум маркировка, A, B. Для A/B сначала natural имя объекта,
   затем панель/порт, затем ID. Отдельная сортировка «по порту» полезна
   внутри выделенной стороны и устройства, иначе одинаковые «1» теряют
   контекст. Поддержка последовательного выбора разных колонок обязательна
   для этого UX; одновременные пользовательские ключи — отдельное решение.
4. Предметные фильтры комбинируются: объект, сторона (любой/A/B), порт
   выбранного объекта, наличие маркировки. При смене объекта очистить
   неприменимый порт с видимой обратной связью. Оборудование — Location,
   direct/subtree по принятому правилу, тип, порты, карта как отдельный
   presentation filter. Статус Cable имеет смысл при нескольких значениях.
5. Длинный результат разбивается на страницы; варианты 25/50/100 и
   «показано 26–50 из 87» с общим числом совпадений. При изменении фильтра
   или размера — первая страница, изменение числа объявляется. После
   удаления на опустевшей последней странице — последняя доступная.
6. Восстановить запрос, сортировку, страницу и строку на Back и при
   возврате из карточки. Пустой набор и 0 совпадений различать, дать
   сбросить фильтр. При ошибке refresh обозначить stale данные и повтор
   чтения отдельно от повторной записи.
7. Клиентская обработка допустима для ограниченного набора (порты
   одного объекта/панели, селекторы и небольшие справочники). Для
   общеорганизационных списков оборудования и Cable ожидается серверная
   выборка, которая сортирует и фильтрует весь подходящий набор до
   формирования страницы. Выбор реализации после измерения объёма,
   времени ответа, payload и рендера. 48–100 записей проверяют UX и
   устойчивость порядка, throughput из этого не следует.
8. Маппинг, explicit spatial order, ревизионные diff и preview серии
   сохраняют доменный порядок. В bulk connect ASC/DESC кандидатных
   портов влияет на pairing и должен быть явно отделён от просмотра уже
   сопоставленных пар. Массовая операция показывает scope и число
   затронутых записей независимо от страниц.

## 13. Suggested bounded corrective workstreams

## 14. Open product decisions

1. Оставить два представления в «Каталоге» или выделить Кабели отдельным
   пунктом, когда частота переходов это оправдает. Для обоих вариантов
   нужен адресуемый список.
2. По умолчанию для стойки показывать прямые назначения, для здания
   предложить явный режим «с дочерними»; решить default и способ
   обозначения охвата. UUID Location обязателен при одинаковых названиях.
3. Что входит в исходный table scope: single active sort или настраиваемая
   цепочка, размер по умолчанию и правила хранения, нужен ли bulk именно
   из списка. Для destructive bulk сначала согласовать scope и явный
   preview. Именованные сохранённые выборки — позже при подтверждённой нужде.
4. Где показывать короткий technical ID, полный ID и отсутствие
   маркировки; какие термины используются для A/B в недирективной связи.
   Фильтр «любой конец» сохраняет симметрию.

   удалённому окончанию, как показывать пользователю полный контекст
   панели и повторяющиеся имена. Выбор относится к навигации.

## 15. Acceptance criteria and evidence index

В Chromium проверено 8 UC, включая сценарии с наблюдаемыми
ограничениями, и 18 экранов/представлений. Единица учёта — отдельная
задача или route: 7 входов sidebar, отдельно логическая карта,
Кабели и Модули, создание объекта, три раздела его карточки и четыре
экрана create/edit шаблонов. Диалоги в это число не входят.

Внешний review должен сверить каждый finding с браузерным событием или
кодовым механизмом, проверить границы и отдельно одобрить targets.
Минимальный повтор будущего исправления — прогоны UC-01–08 на двух
viewports, 48 и 100 Cable с ручными метками, шаблоном, без метки и с
одинаковыми подписями портов. В UX-критерии входят точные переходы,
доступные кнопки, состояния пустоты/ошибки и отсутствие потери контекста.
Негативные проверки модальных окон включают перекрытие, возврат focus,
пустую выборку и отказ загрузки. Состояния подключения, trace semantics и
canonical identity оцениваются по принятым L1-контрактам.

### Воспроизведение выборки

1. В чистом экземпляре запустить `docker compose -p netmap-ux-ia-audit-01 -f compose.perf.yaml up -d --build perf-db perf-backend perf-frontend`. Открыть порт 5174.
2. В Locations создать Campus → Building → Floor → Room → Rack и Annex под Campus с префиксом AUD-. Под Room создать серию AUD-Shelf-## от 1 до 28. Добавить AUD-Tray из Rack, открыть reparent Rack, выбрать Annex и проверить потомка. Для проверки серии повторно открыть действие у Room после создания 28 строк.
3. Создать справочный AUD-RJ45 и BaseTemplate AUD-48 с 48 Network Ports на одной панели. В каталоге создать AUD-SW-A, выбрать Rack через поиск в Location picker, затем создать AUD-SW-B. В библиотеке создать AUD-NIC с совместимостью AUD-SLOT.
4. Создать AUD-Map. Из обзора каждого объекта выбрать «Добавить на карту», AUD-Map, «Добавить». Открыть карту через ссылку в карточке B. При необходимости использовать Fit и сдвинуть пустое полотно, чтобы видеть B. В меню B открыть «Массовое подключение», выбрать A, выбрать все свободные порты обеих сторон, сопоставить, просмотреть 48 пар и создать без имён.
5. Повторить UC-03–05 на обоих размерах, создать шаблон метки AUD-Label с AUD-C-##, одну метку сгенерировать, одну ввести вручную. Для UC-08 открыть оба конца одной маркированной строки. Для отдельного просмотра ordinary connect создать свободный AUD-SW-C и открыть действие на его физической строке.

Ещё не проверены 100 строк, исчерпывающие keyboard/touch и screen reader,
полная локализация EN, живые NetBox/Nautobot и новый полный цикл
переподключения/конфликтов. Работа с reconnect сверена с исходниками и
[историческим браузерным evidence](l1-readiness-evidence/ux-review/dialog-reconnect.png).
