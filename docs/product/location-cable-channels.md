# Кабель-каналы между Location

## Согласованная пользовательская семантика

Пользователь выбирает исходный и конечный Location и создаёт между ними
кабель-канал. Его концами являются два Location, а не PhysicalObject или порты.
Канал имеет две точки привязки к границам выбранных Location и редактируемую
промежуточную трассу по аналогии с MapCableRoute. Точки следуют за изменением
геометрии соответствующего Location.

Кабели между портами разных Location могут использовать существующий канал
как общий участок отображаемой трассы:

`порт A → граница Location A → общий кабель-канал → граница Location B → порт B`.

Каждый Cable сохраняет собственные canonical identity, Connection,
ConnectionMember mapping и endpoints своего Connection. Канал не создаёт и
не изменяет connectivity, не доказывает реальный физический маршрут.
L1 trace использует только точные canonical Connection/ConnectionMember/Cable
facts; геометрические пересечения и принадлежность Location не дают evidence.

Канал — сохраняемое presentation state конкретной SavedMap/компоновки,
не новый canonical PhysicalObject, ConnectionPoint, Connection или Cable.
Canonical Location hierarchy остаётся источником вложенности и принадлежности
объектов. SavedMap не становится источником topology.

## Видимость границ и рекурсивное сворачивание

Наличие канала не требует показывать всю иерархию Location. Для каждого L
поддерево включает сам L и всех его descendants. Канал требует видимой
границы L, если ровно одна его конечная Location входит в это поддерево.
Это проверка canonical hierarchy, а не пересечения нарисованных линий.
Канал между двумя детьми одного родителя сам по себе не требует рамки родителя.

Обычное singleton/unary упрощение не скрывает необходимую из-за канала
границу. Явное сворачивание родителя имеет приоритет: канал не раскрывает
скрытых детей или внутренние детали. Полностью внутренние каналы скрываются;
пересекающие внешнюю границу свёрнутого Location остаются представлены на его
видимой границе. Это presentation representation, а не смена концов канала.
Сохранённая геометрия не уничтожается. При разворачивании восстанавливаются
дочерние Location, их каналы и сохранённая компоновка с применением сохранённых
состояний детей. Правила действуют рекурсивно на любой глубине.

| Сценарий | Требование только из-за канала |
| --- | --- |
| A и B — дети P | Границы A/B нужны; рамка P не обязательна. |
| A внутри P, B снаружи P | Граница P нужна; singleton её не скрывает. |
| P явно свёрнут, A/B внутри P | Канал скрыт, дети не раскрываются. |
| P явно свёрнут, A внутри, B снаружи | Канал представлен на границе P без внутренних деталей. |

## Существующие механизмы — не реализация канала

[Spatial contract](../architecture/presentation/09-spatial-location-mapreference-contract.md)
задаёт canonical hierarchy, derived frames, варианты, recursive collapse и
сохранение route geometry при collapse/expand. Для каналов выше согласовано
будущее исключение из unary упрощения, а не объявлено изменение renderer.

MapCableRoute и MapLocationBoundaryAnchor (`location_id`, `edge`, `offset`)
релевантны как механизмы редактируемой трассы и boundary binding. Они не
являются готовой реализацией канала. [Редактор маршрутов](../plans/11-08-cable-route-editor-completion.md)
сохраняет собственную геометрию Cable; cross-route snapping не сохраняет
общую зависимость. [Canonical Cable model](../architecture/l1/01-01-02-cable.md)
и [пользовательские справочники](user-reference-catalogs.md) не меняются.

## OPEN implementation decisions

- Persistence, API, DTO и точный lifecycle канала и его связи с Cable.
- UX назначения/снятия Cable и редактирования подводов, общего участка и anchors.
- Разрешение видимых anchors при nested/partial collapse и восстановлении;
  геометрия для Location без renderable frame остаётся OPEN, без guessed bounds.
- Поведение при изменении canonical hierarchy, удалении Location/Cable,
  копировании вариантов и изменении геометрии общего участка.
- Алгоритм поиска подходящих каналов и выбор между несколькими каналами.

Здесь не выбираются таблицы, миграции, окончательные DTO или алгоритмы.
Не вводятся canonical CableBundle, физический учёт лотков, автоматическое
создание каналов, маршрутизация через произвольный граф Location или
performance refactoring. Существующие критерии C-UX-10, включая счётчик
кабелей и точное trace evidence, этим контрактом не отменяются.
